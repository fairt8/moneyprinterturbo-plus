# AI visuals, Gemini voice, and autopilot

## Visual source `gemini_image` (default)

1. The narration is split into scenes of about 4 to 5 seconds.
2. The script LLM writes one concrete photo prompt per scene.
3. Each scene image is generated by the first provider that works:
   - Google: `imagen-4.0-fast-generate-001`, `imagen-4.0-generate-001`,
     `imagen-3.0-generate-002`, `gemini-2.5-flash-image`,
     `gemini-3.1-flash-lite-image`, `gemini-3.1-flash-image`
     (override with `GEMINI_IMAGE_MODELS`). These need billing on the
     Google Cloud project behind `GEMINI_API_KEY`; the free tier has 0 image
     quota, so they are skipped for an hour after a refusal.
   - Cloudflare Workers AI, FLUX.1 schnell, through the `mpt-ai-image` Worker
     (`CF_IMAGE_URL`, `CF_IMAGE_KEY`). Free daily allowance on Workers AI.
   - Pollinations (opt-in, `AI_IMAGE_FREE_FALLBACK=true`).
4. FFmpeg renders every still with a slow zoom or pan and joins scenes with
   0.45 s crossfades into one track.
5. If fewer than 60% of scenes get an image, the task uses
   `ai_image_fallback_source` (default `pixabay`) instead.

The scene list, prompts and providers are saved in each task's `script.json`
under `ai_visuals`.

## Voice

`gemini:<Voice>-<Style>` voices use Gemini TTS. Models tried in order:
`gemini-2.5-flash-preview-tts`, `gemini-3.1-flash-tts-preview`,
`gemini-2.5-pro-preview-tts` (override with `GEMINI_TTS_MODELS`). If all fail,
Edge TTS `tts_fallback_voice` (default `en-US-AndrewNeural`) is used.

## Script LLM fallback

If the configured LLM returns an error, the request is answered by Gemini
text models (`LLM_GEMINI_FALLBACK=true`), and the primary is skipped for five
minutes.

## Autopilot

A worker thread in the API container. Settings in `.env`:

| Variable | Default |
|---|---|
| `AUTO_SCHEDULE_ENABLED` | `false` |
| `AUTO_SCHEDULE_TIMES` | `09:00,18:00` |
| `AUTO_SCHEDULE_TZ` | `Africa/Lagos` |
| `AUTO_SCHEDULE_PER_DAY` | `2` (uses the first N times) |
| `AUTO_SCHEDULE_NICHE` | `personal finance and money tips` |
| `AUTO_SCHEDULE_CHAT_ID` | first Telegram admin id |
| `AUTO_SCHEDULE_VOICE` | `gemini:Charon-Informative` |
| `AUTO_SCHEDULE_SOURCE` | `gemini_image` |
| `AUTO_SCHEDULE_GRACE_HOURS` | `0.5` (catch-up window after a restart) |
| `AUTO_PUBLISH_ENABLED` | `false` |
| `AUTO_PUBLISH_PRIVACY` | `public` |

Each run picks a topic not used before (last 120 kept in
`storage/autopilot/state.json`), renders it, sends the MP4 and a ready-to-post
title, description and hashtags to Telegram, then deletes the render. With
`AUTO_PUBLISH_ENABLED=true` and accounts linked under `/accounts`, the video
is also queued on every linked YouTube and TikTok account. A failed run is
retried once after ten minutes.

API (needs `x-api-key`):

- `GET /api/v1/autopilot` shows the schedule, queue and recent runs.
- `POST /api/v1/autopilot/run` with `{"count": 2}` or `{"topics": ["..."]}`
  queues videos now. `"keep": true` leaves the file until the retention window.
